# 个人中心实施与认证接入说明

## 仓库现状与范围

- 前端 Vue 3.5 / Pinia 3 / Vue Router 4（Hash 路由）/ Element Plus 2，后端独立 Nest 项目。
- 实施前没有用户 Store、Header 用户菜单、认证守卫、账号接口或登出流程。现有 Axios 请求封装在 `src/utils/request.ts`：没有 Token 注入或统一 401 登出，仅显示请求错误。
- 已有 Node 内置测试。本次沿用，没有添加依赖、改写业务 API 或实现业务库密码存储。
- 当前登录页仍为前端预览，没有真实登录能力。工作台继续允许体验访问，不增加伪认证守卫。

## 当前接口状态

**未接入任何账号 HTTP 地址。** 不会调用文档示例 `/api/account/me` 或 `/api/account/password`，不会宣称示例接口已上线。未安装适配器时，资料明确提示未接入、账号显示 `--`、密码提交不会请求或假成功。

运行时没有 Mock 账户，也没有模拟密码成功。测试内的 Mock 仅验证适配契约。

## 后续需要提供的真实契约

1. 登录：方法、地址、请求/响应结构、身份来源、Token/Cookie 和刷新规则。
2. 当前用户：方法、地址、用户字段、角色结构、邮箱/手机号隐私展示规则。
3. 密码策略：获取方式及可公开说明、长度上下限；服务端仍负责完整策略、泄露密码与复用检查。若策略是已确认的固定契约，可由适配器返回契约值，不要求后端一定增加策略接口。
4. 修改密码：实际地址、请求格式、响应及错误码、频控/Retry-After、超时策略。UI 层只提交 `oldPassword` 和 `newPassword`；如后端命名不同，由适配器映射。禁止提交目标 userId 或确认密码。
5. 会话：密码修改后当前会话保留/刷新/失效，其他会话是否撤销；登出接口及本地凭据清理项。
6. Cookie 场景的 CSRF、跨域与 HTTPS 部署要求。

## 安装适配器

在应用启动、挂载前调用 `installAccountAdapter(realAdapter)`，实现 `AccountAdapter` 的六个方法。未接入阶段不要安装空实现或把任意响应当成功。

- `getMe`：归一化真实用户。联系方式须由适配层按系统规则脱敏后赋给 `maskedEmail` / `maskedPhone`。未知字段不编造。
- `getPasswordPolicy`：返回已确认的公开策略。前端仅验证必填、一致性、新旧差异和服务端长度；其他规则由认证中心验证。
- `changePassword`：使用已确认的请求封装。验证响应业务成功，并明确返回 `session: 'keep' | 'reauthenticate'`，不能在缺少会话契约时默认保留。需要刷新 Token 时，必须先实际完成刷新才能返回 `keep`。
- `otherSessionsRevoked`：只有服务端确认真实执行才传 `true`。否则不显示其他设备已退出。
- `logout`：完成服务端登出和当前认证客户端清理；失败抛错，UI 保留当前页供重试。不得用 `localStorage.clear()` 替代，也不要删除无关创作数据。
- `clearSession`：会话失效时完成本地凭据、刷新任务、认证缓存等清理，不再次发起需要有效登录态的登出请求。

适配器把服务端错误转换为 `AccountError`，不能将带有请求配置、密码或原始响应的错误交给通知/日志。401 映射 `expired`，429 映射 `rateLimited`，网络错误映射 `network`，5xx 映射 `server`，密码错误映射 `oldPassword` / `policy` / `reused`。适配器还需执行真实重试等待规则；UI 不会自动重试密码请求。

现有业务 Axios 拦截器会显示服务端原始 message，因此**在后续真实接入时应支持账号调用静默错误，并在统一入口归一化错误**，避免重复提示或泄露敏感内容。本次未为尚未确定的账号协议改动业务请求行为。完成登录、认证请求拦截器和守卫接入后，再统一其他业务接口的 401 流程；当前只预留账号侧失效处理。

## 会话与敏感数据

密码只在弹窗组件局部状态及正在执行的请求中使用。取消、关闭、组件卸载清空；请求中不能关闭或重复提交。旧密码错误清空当前密码，保留可修正的新密码；成功后立即清空全部输入。关闭再打开会重新获取策略。

用户信息仅在 Pinia 内存中，无密码、Token 的浏览器存储或 URL 写入。会话清理失败会提示重新登录，不宣称清理已成功。现阶段“返回登录页”只是离开预览，不能等同真实会话撤销。

## 人工验收步骤

1. 启动前端，在登录页点击体验工作台。右上角应显示“预览模式”。
2. 点击用户菜单：个人信息进入 `/#/profile`，账号显示 `--`，没有虚构租户或角色；没有左侧个人中心菜单。
3. 分别从用户菜单和个人信息页打开修改密码，确认均为相同弹窗。
4. 空字段提交显示对应错误；新旧相同、两次新密码不同应被拦截；默认隐藏，显隐按钮和密码管理器可用。
5. 有效输入提交应提示账号服务/策略未就绪，网络面板没有账号请求，没有成功提示。
6. 取消、关闭或离开工作台，再打开，三个密码框均为空。窄屏检查菜单、表单和弹窗不超出视口，使用 Tab 检查焦点与关闭。
7. “返回登录页”应回到登录页，不清除无关本地创作历史。
8. 真实接入后追加联调：用户资料加载失败重试；旧密码错误；策略拒绝；401/429/5xx/断网；双击仅一次请求；成功保留/失效会话两条路径；退出与 Token 清理；检查请求仅含允许的两个密码字段、日志不含密码。

## 与方案的阶段差异

由于用户明确要求真实接口后续提供，本次交付前端和可替换适配层，真实认证联调作为后续事项。未虚构 HTTP 协议、固定密码策略、已登录用户或已执行的会话撤销。没有原登出流程可复用，因此将真实登出集中为单个适配器入口；上线前必须完成该入口及登录/401/守卫的一致性验证。
